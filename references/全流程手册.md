# 邮箱商机库 · 全流程手册

> 目标：把某个邮箱（由配置指定）的邮件做成商机基础数据：
> 索引 → 过滤线程化 → 抓正文 → 导出批 → AI 抽卡 → 导入 + 报告。
> 全程 **IMAP 只读**（readonly + BODY.PEEK），不发邮件、不改服务器、不发布在线链接。
> 卡片不写银行账号/密码/license key/授权码；授权码只在本地 .env（600）。

---

## 关键路径（全部来自 config）

工作目录 `<WS>` = `pipeline_config.json` 的 `workspace`。
- 数据库：`<WS>/<db_name>`（默认 `mail_index.sqlite`）
- 抽取目录：`<WS>/<out_dir_name>`（默认 `抽取/`）
- 程序/日志：`<WS>/<program_dir_name>/`（默认 `邮件归档程序/`，日志在其 `logs/`）
- 配置：`<WS>/pipeline_config.json`；凭据：`<WS>/<program_dir_name>/.env`

Python 命令统一记为 `PY`。在 WorkBuddy 环境用其管理的 python3（形如
`env -u PYTHONPATH <python3绝对路径>`），其它环境用 `python3`。
所有脚本都在 `<skill>/scripts/` 下，运行时把该目录加入 `PYTHONPATH` 或 `cd` 进去。

## 阶段判定（每轮先查，按第一个未完成的阶段执行）

### 阶段 0：配置与连通（setup）
- 未配置：运行 `python3 scripts/setup.py`，按提示填工作目录、IMAP 服务器/账号/授权码、
  你方公司/域名/负责人、起始日期、客户文件夹前缀。生成 `pipeline_config.json` + `.env`（均 600）。
- 验证：`python3 scripts/check_setup.py`，必须全绿（会只读登录并打开 INBOX，不打印授权码）。

### 阶段 A：索引（step1_index）
- 判据（以日志为准）：`tail -5 <日志>/step1.log` 末尾出现「第①步完成」即视为完成。数量仅参考。
- 未完成：看日志最后时间戳——距今 < 15 分钟说明后台仍在跑，**本轮不动，直接结束**。
- 若日志 > 15 分钟未更新且无完成标记：重跑（按 folder+uid 跳过已抓，幂等续跑）：
  ```
  $PY step1_index.py
  ```
- 首次可对单个文件夹小试：`--folders INBOX --limit 50`。

### 阶段 B：过滤线程化（step2_filter）
- 判据：库 `threads` 表行数是否稳定（首次从 0 变正数）；再跑一次行数不再增长即完成。
- 执行：
  ```
  $PY step2_filter.py --db <WS>/mail_index.sqlite
  ```
- 完成后进入阶段 C（同一轮可继续）。

### 阶段 C：正文抓取（step3 系列）
- 判据（**排除已判正文为空的邮件**）：
  ```sql
  select count(*) from messages m
  where m.kept=1 and m.is_dup=0 and m.exclude_reason is null
    and not exists(select 1 from bodies b where b.folder=m.folder and b.uid=m.uid)
    and not exists(select 1 from errors e where e.folder=m.folder and e.uid=m.uid and e.error like '%正文为空%')
  ```
  为 0 才算完成。拿不准时保留，避免反复重抓浪费配额。
- 收敛容错：若该数 < 200，视为完成进 D（多为纯附件邮件，正文确实取不到）。
- 长连接断开：数小时后台跑后 IMAP 长连接会断，整文件夹被跳过、待抓数降不下来。
  改用健壮版（每文件夹新连接、失败重试 5 次）：
  ```
  $PY step3e_resume_bodies.py --db <WS>/mail_index.sqlite
  ```
- 防并发：正文抓取耗时长；若后台在跑（日志 mtime < 15 分钟）**本轮不动**，绝不启第二个。

### 阶段 D：导出批（export_fast）
- 判据：抽取目录下是否已有 `<tag>batch_*.txt`。
- 执行：
  ```
  $PY export_fast.py --db <WS>/mail_index.sqlite --out <WS>/抽取 --tag <tag> --ready-only --chars 250000
  ```
- 导出后跑编排器 `status → next -n 4`。

### 阶段 E：抽卡（循环，无人值守核心）
1. `run_batches.py import → gaps → status → next -n 4`
2. 对拿到的批号，一条消息并行派 ≤4 个子代理，每个做一批。
   - 派发模板见 `references/子代理任务模板.md`；规格见 `references/抽取规格.md`。
   - 自检：`python3 scripts/verify_jsonl.py <txt> <jsonl>` 必须通过。
3. 全返回后 `run_batches.py import → verify → status`；本轮最多 2 轮。
4. 报 429/网络错：先看对应 jsonl 是否已生成，生成就直接 import，不重抽。
5. 若 status：pending 0 / partial 0 / ready 0 → 回阶段 D 再导出一轮；确实无新批 → 进 F。

### 阶段 F：合并 + 收尾
1. 备份数据库：
   ```
   cp <WS>/mail_index.sqlite <WS>/mail_index.sqlite.PRE$(date +%Y%m%d_%H%M%S)
   ```
2. 收尾（重生成报告、WAL 落盘、chmod 600）：
   ```
   $PY finalize.py
   ```
3. 校验产物权限与卡片行数；向用户汇报完成度。

## 编排器 run_batches.py 子命令

| 命令 | 作用 |
|---|---|
| `status` | 总览：pending/partial/ready/done、线程覆盖、库内卡片数，刷新进度看板 |
| `next -n K` | 打印接下来该做的 K 个批号（按年段优先级） |
| `gaps` | 给有缺漏的批生成 `*_gap.txt`（只含缺的线程） |
| `import` | 导入所有已产出未导入的 jsonl（幂等，自动修复坏行） |
| `verify` | 校验所有 jsonl 的字段合法性 |

批状态：pending（无 jsonl）/ partial（jsonl 有缺漏）/ ready（齐了未导入）/ done（已导入）。

## 硬性约束
1. 邮件服务器只读：`select(readonly=True)` + `BODY.PEEK[...]`，绝不 STORE/COPY/MOVE/EXPUNGE/APPEND。
2. 不发任何邮件/IMAP 写操作，不发布在线链接。
3. 卡片不写银行账号/IBAN/SWIFT/密码/license key/授权码；含凭据被审批拦截只记 skip，不绕过不推断。
4. 授权码只从本地 .env 读取，不打印、不写进任何产出、不上传。
5. 合并/收尾前先备份数据库。

## 常见排错
- **连不上 IMAP**：先跑 `check_setup.py`。企业邮箱多为 993+SSL；授权码不是登录密码，需在邮箱设置里开启 IMAP 并生成授权码。
- **进度不动**：多半后台仍在跑（日志 mtime < 15 分钟），等待即可，勿并发启动。
- **待抓数降不下来**：长连接断了，换 `step3e_resume_bodies.py`。
- **某批大量 skip「审批拦截」**：把该批 txt 拆成小块（每块几条线程）重抽——小块不易触发敏感内容审批超时；166 批曾整份被拦，拆 5 块后全通过。
- **子代理输出坏 JSON**：`import` 会自动修复结构性坏行；仍不行用 `gaps` 重抽缺的线程。
- **429 额度用尽**：已产出的 jsonl 直接 `import`，不重抽；等额度恢复再派新批。
