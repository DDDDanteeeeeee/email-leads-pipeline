# 抽取规格（第④步 · 邮件商机卡片）

> 本文件是**唯一口径来源**。所有批次、所有子代理必须严格按此执行。
> 数据源：配置里指定邮箱的邮件线程。你方公司名/负责人从 `pipeline_config.json` 的
> `our_company` / `owner_name` / `our_domain` 读取；若某个字段未配置，按下方说明填 null。

---

## 一、你的任务

读入一批邮件线程文本，为**每个线程**输出一个 JSON 对象（一行一个），写入指定 JSONL 文件。

- 一个线程若包含**多个彼此独立的实质商务主体**（例如同一主题下先谈 A 客户、后谈 B 客户），可按主体拆成多张卡片；否则一个线程一张卡。
- 纯行政/通知/无实质内容的线程，输出 `{"record_id": "...", "skip": "原因"}`。

---

## 二、输入格式

```
### RECORD <thread_id> | email_thread
Subject: ...
Folder: ...
Span: 2024-03-01 ~ 2024-03-20 | 5 messages

--- [1/5] 2024-03-01 10:22 | from: alice@acme.com | folder: INBOX
正文……
--- [2/5] ...
```

注意：
- 中间封可能被截断到前 300 字（末尾有 `…`），首封与最后 6 封是全文。
- `Folder` 为客户归档文件夹名，是"这封信属于哪家客户"的标签。
- 正文已清洗掉引用历史与签名档，但仍可能残留少量噪声。

---

## 三、输出字段（严格照此，不多不少）

```json
{
  "record_id": "线程 id，原样照抄 ### RECORD 后的值",
  "thread_id": "同 record_id",
  "source_type": "email_thread",
  "date_first": "YYYY-MM-DD",
  "date_last": "YYYY-MM-DD",
  "company": "外部公司名（原文写法，不要翻译、不要臆造）",
  "domain": "该公司的主域名，如 acme.com；无法判断填 null",
  "country": "国家/地区中文标准名，如 美国 / 德国 / 日本 / 中国香港；无法判断填 null",
  "contacts": [{"name": "姓名", "title": "职位或 null", "email": "邮箱或 null"}],
  "company_type": "分销商|集成商|经销商|终端用户|OEM定制|顾问|媒体|竞品|供应商|其他",
  "industry": "行业，中文，如 广电 / 教育 / 医疗 / 企业 / 政府 / 场馆演出；不明填 null",
  "end_customer": "终端客户或项目名，原文；无则 null",
  "signals": ["从下方 12 类中选，可多选，至少一个"],
  "products": ["涉及的产品型号，原文写法；无则 []"],
  "competitors": [{"brand": "品牌", "model": "型号或 null", "point": "原文提到的对比点"}],
  "quantity_or_value": "原文出现的数量/金额，照抄（如 47 units / USD 121,451.40）；无则 null",
  "product_feedback": "中文，产品层面的反馈/问题；无则 null",
  "trend": "中文，反映的市场/需求趋势；无则 null",
  "summary": "中文，3-5 句说清：对方是谁、要什么、进展到哪、金额或数量、卡在谁那里",
  "open_question": "中文，下一步待办或卡点；status 为「已结束」时填 null",
  "status": "未回复|回了但未闭环|中断|已结束|待确认",
  "our_people": ["你方参与人，邮箱或姓名"],
  "owner_involved": "发件人|收件人|抄送|群里发言|未出现",
  "evidence": ["逐字摘录原文的关键句，2-4 条，不改写不翻译"],
  "notes": "中文，其他值得记的（风险提示、数据异常、敏感信息已脱敏说明等）；无则 null",
  "folder": "线程所在的客户文件夹名，照抄输入的 Folder 字段；无则 null",
  "batch": "批次文件名"
}
```

### 12 类信号（signals，中文，只能用这些词）
`询价`、`项目机会`、`渠道合作`、`样机测试`、`定制OEM`、`采购`、`风险投诉`、`引荐`、`产品需求`、`竞品情报`、`技术问题`、`市场趋势`

### status 口径
- `未回复`：对方来信，我方未回
- `回了但未闭环`：我方回过，但事情没有结论（等对方、等内部、等报价批复）
- `中断`：有明确终止迹象（对方明确不做、项目取消、长期无响应且已过合理周期）
- `已结束`：有明确结论（成交/交付完成、明确拒绝且无后续、问题已解决）
- `待确认`：信息不足以判断

### 业务字段口径（可配置）
- `our_people`：你方参与人。识别方法——发件人/收件人邮箱域名等于配置里的 `our_domain`。
- `owner_involved`：配置里的 `owner_email`（或 `owner_name`）在本线程中的角色；未配置 `owner_email` 时按你方主账号判断，仍无法判断填「未出现」。

---

## 四、语言规则

| 字段 | 语言 |
|---|---|
| `summary`、`open_question`、`product_feedback`、`trend`、`notes`、`industry` | **中文** |
| `company`、`products`、`evidence`、`quantity_or_value`、`end_customer` | **保留原文，不翻译** |
| `signals`、`company_type`、`status`、`owner_involved`、`country` | 受控词表（中文标准词） |

`evidence` 必须**逐字**摘录输入正文中的原句，一字不改、不翻译。若原文是英文就写英文。

---

## 五、硬性约束

1. **不编造**。原文没写的数量、金额、型号、人名，一律 `null`，不要推算、不要"合理估计"。
2. **敏感信息不入卡**。银行账号、SWIFT/IBAN、BSB、密码、license key、授权码、身份证号等一律不写入任何字段。可在 `notes` 写「正文含银行账号，属敏感凭据，本卡不记录」。
3. **company 用原文写法**。同一公司不同批次写法不同照抄即可，后续由主表统一。
4. **日期**用邮件实际日期，`YYYY-MM-DD`。
5. 输出必须是**合法 JSON**，一行一个对象，UTF-8 无 BOM。不要在 JSONL 里加注释、空行或 markdown 代码块。

---

## 六、跳过规则

以下类型输出 `{"record_id": "...", "skip": "原因"}`：
- 纯日历回执、会议邀请（无实质商务内容）
- 群发通知、系统告警、物流/快递通知
- 纯行政事务（报销、考勤、发票开具的模板通知）
- 空正文或只有问候语
- 内部同事之间的日程协调

注意：**只要线程里出现了任何实质性商务信息（询价、项目、产品问题、订单、竞品、渠道），就不要跳过，必须出卡。**

---

## 七、自检（必须做）

写完后运行（Python 用环境里的 python3）：
```
python3 verify_jsonl.py <批文件.txt> <产出.jsonl>
```
必须通过：每行可解析、卡片+跳过==线程数、id 全覆盖、signals/status 合法、无敏感凭据。
有缺失就补抽，有违规就修正，然后重跑自检。

---

## 八、最终交付

- 只写你被指定的那一个 `.jsonl` 文件
- 不要修改数据库、批文件、规格文件或其他批次的 jsonl
- 完成后用不超过 200 字报告：线程数 / 卡片数 / 跳过数 / 缺失数 + 3 条最值得业务负责人看的发现
