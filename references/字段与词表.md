# 字段与词表速查

## 卡片字段（business card schema）
`record_id`、`thread_id`、`source_type`、`date_first`、`date_last`、`company`、`domain`、
`country`、`contacts`、`company_type`、`industry`、`end_customer`、`signals`、`products`、
`competitors`、`quantity_or_value`、`product_feedback`、`trend`、`summary`、`open_question`、
`status`、`our_people`、`owner_involved`、`evidence`、`notes`、`folder`、`batch`。

数据库 `cards` 表字段与上表一致，另加 `card_id`（自增主键）、`raw`（整条 JSON）、`extracted_at`。
`card_skips` 表：`record_id`、`skip`、`batch`、`extracted_at`。

## 受控词表

**signals（12 类，可多选，至少一个）**
询价 / 项目机会 / 渠道合作 / 样机测试 / 定制OEM / 采购 / 风险投诉 / 引荐 / 产品需求 / 竞品情报 / 技术问题 / 市场趋势

**status（5 值）**
未回复 / 回了但未闭环 / 中断 / 已结束 / 待确认

**company_type（10 值）**
分销商 / 集成商 / 经销商 / 终端用户 / OEM定制 / 顾问 / 媒体 / 竞品 / 供应商 / 其他

**owner_involved（5 值）**
发件人 / 收件人 / 抄送 / 群里发言 / 未出现

**country**：中文标准名（美国、德国、日本、中国香港……）；无法判断 null。

## 语言规则
- 中文：`summary`、`open_question`、`product_feedback`、`trend`、`notes`、`industry`
- 原文不翻译：`company`、`products`、`evidence`、`quantity_or_value`、`end_customer`
- 受控词表：`signals`、`company_type`、`status`、`owner_involved`、`country`
- `evidence` 必须逐字摘录原句。

## 敏感信息黑名单（绝不入卡）
银行账号、IBAN/SWIFT/BSB、密码、license key、授权码、身份证号。
含凭据的邮件正文被审批拦截时，只写 `{"record_id":"...","skip":"正文被敏感内容审批拦截，未能读取"}`。

## 数据库关键表
- `messages`：folder+uid 主键；邮件头、日期、收发件人、主题、去重标记、kept/thread_id。
- `threads`：thread_id 主键；主题、首末日期、消息数、外部域名、我方参与人、客户文件夹标签。
- `bodies`：folder+uid 主键；正文文本、字符数、抓取时间。
- `errors`：抓取失败记录（含「正文为空」的真空邮件）。
- `cards` / `card_skips`：抽卡结果。
- `folders`：文件夹清单与 UIDVALIDITY。
