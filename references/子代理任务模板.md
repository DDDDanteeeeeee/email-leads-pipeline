# 第④步 子代理任务模板

> 用法：把 `{{TXT}}`（批文件绝对路径）、`{{JSONL}}`（产出绝对路径）、
> `{{N}}`（线程数）、`{{LINES}}`（行数）、`{{CHARS}}`（字符数）、
> `{{PY}}`（python 解释器命令）替换后派发。
> 一批派一个子代理，一条消息最多并行 4 个。

---

你在为一个邮箱的「商机原始数据库」做第④步 AI 抽取。这是全量抽取中的一批。
你的唯一产出是一个 JSONL 文件。

**第一步，先读规格文件（唯一口径来源）：**
`<skill目录>/references/抽取规格.md`

**第二步，读批文件：**
`{{TXT}}`
共 {{LINES}} 行、{{CHARS}} 字符、{{N}} 个线程（以 `### RECORD <id> | email_thread` 分节）。
文件较大，用 Read 分多次读完（每次约 1000 行，offset 递增）。**必须完整读完，不要跳读**——漏掉的线程在自检时会暴露。

**第三步，写出结果：**
`{{JSONL}}`（每行一个 JSON 对象，UTF-8 无 BOM，无代码块无空行）。用 Write 工具。
- `batch` 字段填批文件名；`folder` 照抄输入 `Folder:` 值。
- 你方公司/负责人信息从 `<工作目录>/pipeline_config.json` 读取；字段口径见规格。

**第四步，自检（必须做）。** 用 Bash 运行：
```
{{PY}} <skill目录>/scripts/verify_jsonl.py "{{TXT}}" "{{JSONL}}"
```
必须通过；不过就按提示补抽/修正后重跑，直到通过。

**关键约束：**
1. `summary` / `open_question` / `product_feedback` / `trend` / `notes` 用**中文**；
   `company` / `products` / `evidence` / `quantity_or_value` 保留**原文，不翻译**；`evidence` 必须逐字摘录。
2. `status` 为「已结束」时，`open_question` 填 `null`。
3. 银行账号、SWIFT/IBAN、BSB、密码、license key、授权码一律不写入任何字段；可在 notes 注明「正文含 xxx，属敏感凭据，本卡不记录」。
4. 金额/数量/型号原文没写就 `null`，不推算。
5. 只写这一个 jsonl。不要动数据库、批文件、规格文件或其他批的 jsonl。
6. 同一批若 Read 返回敏感内容审批超时，跳过该段、不重试，对该线程写
   `{"record_id":"...","skip":"正文被敏感内容审批拦截，未能读取"}`；务必把文件写出来。

完成后用不超过 200 字报告：线程数 / 卡片数 / 跳过数 / 缺失数 + 3 条最值得业务负责人看的发现。
